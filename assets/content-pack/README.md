# Контент-пакет

## Что это и откуда берётся

Контент-пакет — исходный текстовый материал, из которого пайплайн собирает презентацию: бриф, назначение колоды и фактура (тезисы, цифры, цитаты).

**Контент-пакет — наш собственный артефакт, а не входные данные извне.** ТЗ в разделе «Ресурсы» перечисляет состав пакета так: «3 шаблона презентаций; контент-пакет (не представлен)». То есть организаторы его не выдают, и ждать его не нужно — мы пишем произвольный текст сами.

## Один пакет на все прогоны

Один и тот же контент-пакет используется:

- для всех девяти презентаций (3 калибровочных шаблона × 3 варианта верстки);
- для end-to-end демонстрации на внешнем шаблоне из `../templates/acceptance/`.

Причина: ТЗ требует «три варианта презентации, сгенерированные **на одном контенте** на трёх разных шаблонах». При неизменном контенте видно, что вся разница в результате порождена шаблоном и вариантом верстки, а не подменой исходных данных. Тот же пакет в демонстрации на внешнем шаблоне делает сравнение чистым: меняется только шаблон.

## Требования к содержанию

Пакет должен давать пайплайну работу по всем требуемым возможностям, иначе часть функциональности будет нечем показать:

- **Объём** — достаточный для колоды в 10–15 слайдов.
- **Числовые ряды** — минимум два набора данных, пригодных для диаграмм (требование п. 3 ТЗ: генерация графиков и диаграмм).
- **Табличные данные** — хотя бы один набор, укладывающийся в ограничение аудита (не более 7 строк и 5 колонок).
- **Процесс или этапы** — материал для SmartArt-подобной визуализации.
- **Цитата или тезис спикера** — под соответствующие макеты шаблонов.
- **Фактура для проверки аудита** — все цифры на слайдах должны быть прослеживаемы до этого файла, иначе недетерминированная проверка «все цифры и факты со слайда есть в исходных материалах» не сможет отработать.
- **Язык** — один язык на весь пакет: аудит проверяет единство языка колоды.

Тема выбирается нейтральная и не требующая доменной экспертизы от комиссии.

## Чего в пакете быть не должно

- Готовой структуры слайдов — её генерирует пайплайн, это и есть проверяемая функциональность.
- Указаний на оформление, цвета и макеты — оформление приходит из шаблона.
- Реальных конфиденциальных данных компании.

## Состав

```text
content-pack/
  README.md      этот файл
  brief.md       назначение колоды, аудитория, цель, желаемый объём
  content.md     фактура: тезисы, цифры, таблицы, цитаты
```

`ДОПУЩЕНИЕ` Точный формат (один файл или несколько, Markdown или структурированный YAML) фиксируется на фазе 9 вместе с контрактом входа слоя генерации.

## Статус

Написан 2026-09-28. Тема — защита инициативы по масштабированию программы наставничества «Навигатор».

Что в нём есть под требования выше:

| Требование | Чем закрыто |
|---|---|
| Объём на 10–15 слайдов | 12 тематических блоков, целевой объём задан в брифе |
| Два числовых ряда под диаграммы | Динамика активных пар по 4 кварталам; распределение 137 подопечных по 5 направлениям |
| Таблица в пределах аудита | «Результаты пилота»: 5 строк данных × 4 колонки при лимите 7 × 5 |
| Процесс под SmartArt | Пять этапов участия в паре |
| Цитата | Две: от подопечного и от наставника |
| Прослеживаемость цифр | Все числа заданы в `content.md`; внутренняя арифметика проверена и согласована |
| Один язык | Русский |

**Все данные синтетические** — это указано первой строкой `content.md`. Компания, программа и метрики вымышлены; имена условные.
