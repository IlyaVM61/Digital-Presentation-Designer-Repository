## Что уже установлено

Эти выводы получены и подтверждены, их не нужно перепроверять — на них нужно опираться:

1. **Холст шаблонов различается** (9144000 против 12192000 EMU при одном 16:9). Координаты в схеме — нормализованные доли.
2. **Тема файла систематически расходится с фактическим оформлением.** Тема объявляет Arial, используется Play; в одном шаблоне тема содержит дефолтную палитру Office. Подтверждено и на приёмочном шаблоне. Токены извлекаются из фактической разметки.
3. **Слот не равен плейсхолдеру.** В двух шаблонах из трёх у большинства макетов есть только плейсхолдер заголовка, контент размечен обычными фигурами.
4. **Имена макетов ненадёжны** — в одном шаблоне 11 из 15 макетов называются «Титульный слайд».

## Что осталось изучить

- **Слайды-примеры** — 54, 29 и 55 штук в калибровочных шаблонах. Приоритет высокий: и presenton, и Microsoft Copilot строят выбор макета на слайдах-образцах, а мастера используют как фолбэк (см. `docs/01-research/competitor-analysis.md`). Нужно понять, какие макеты реально применяются, как часто и в каких сочетаниях.
- **Направляющие и поля** — `ppt/viewProps.xml`, а при его отсутствии кластеризация координат повторяющихся элементов. Нужны для проверки «блоки не выровнены по направляющим макета».
- **Логотипы и колонтитулы** — постоянные элементы мастеров и их канонические позиции.
- **Гипотеза о цветовых вариациях:** макеты с префиксами `1_`, `2_`, `3_` в VK Tech могут быть вариантами одного макета в разных цветовых схемах. Если подтвердится — это готовый механизм для генерации визуально различимых вариантов верстки.
- **Диаграммы и таблицы в примерах** — их оформление задаёт правила для генерируемых визуализаций.
- **Контраст пар «текст / фон»** в макетах — базовая линия для проверки 4.5:1.
- **Наследование свойств** по цепочке прогон → абзац → макет → мастер → тема. Парсер обязан разрешать наследование, а не требовать явных значений: именно на этом падает presenton (issue #794).

## Матрица покрытия

`template-coverage-matrix.md` должна показывать, какие типы слайдов поддерживает каждый шаблон: титульный, разделитель, контент, две колонки, изображение, цитата, данные, контакты, финальный. По ней видно, какие типы слайдов пайплайн может генерировать на любом шаблоне, а какие есть лишь в некоторых — то есть где нужен фолбэк.

Ограничения:
- Не писать код. Для чтения шаблонов допустимы разовые скрипты разбора во временной папке, не в проекте.
- Не проектировать архитектуру — только модель шаблона и факты о шаблонах.
- **Не использовать приёмочный шаблон из `assets/templates/acceptance/` для настройки, калибровки порогов или подбора эвристик.** Иначе он перестанет быть приёмочным. Файл из `assets/templates/edge-cases/` шаблоном не является.
- Каждый вывод подкреплять измеримым фактом: числом вхождений, координатами, именами частей пакета. Формулировки вида «шаблон выглядит современно» бесполезны.
