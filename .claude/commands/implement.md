## Окружение

Развёрнуто и проверено. Системный Python не использовать — все команды через окружение проекта:

```bash
D:\venvs\dpd\Scripts\python     # Python 3.12.10, 55 пакетов плюс сам проект (pip install -e .)
D:\venvs\dpd\Scripts\pytest     # тесты
D:\venvs\dpd\Scripts\ruff       # линтер
D:\LibreOffice\program\soffice.com --headless --convert-to pdf   # PPTX → PDF
```

Рендер устроен в два шага: LibreOffice конвертирует `.pptx` в PDF, `pymupdf` рендерит страницы в PNG. `pdftoppm` в системе отсутствует.

Результаты прогонов — в каталог из `DPD_OUTPUT_DIR` (по умолчанию на диске D). На диске C менее 4 ГБ свободного места, туда ничего тяжёлого не писать.

## Порядок работы

1. **Проверь, что архитектура утверждена.** Если фаза 9 не `approved` — остановись и скажи об этом. Код до утверждённой архитектуры запрещён правилами проекта.
2. **Возьми первую невыполненную задачу по порядку из `tasks.md`.** Порядок там не случаен: он начинается с вертикального среза, потому что главный технический риск — нативный экспорт PPTX. Не переставляй задачи ради удобства. Осознанная перестановка помечается прямо в `tasks.md` и обосновывается в `docs/00-status.md` — такой пометке следуй.
3. **Контрольная точка T-10** (пройдена 2026-09-29). После неё должно быть доказано, что мы умеем собрать редактируемый `.pptx` по чужому шаблону и получить его изображение. Если доказать не удалось — остановись и скажи, а не продолжай строить остальное поверх нерабочего экспорта.
4. **Не начинай вторую задачу**, пока первая не завершена и не проверена.
5. **Сначала тест, потом реализация.** Тест должен падать до реализации и проходить после.
6. **Прогони тесты и покажи вывод.** Не заявляй о готовности без вывода команды.
7. **Обнови статус задачи** в `tasks.md`.

## Правила проекта

- **Промпты и конфиги — отдельными файлами** в `prompts/skills/` и `prompts/agents/`. Ни один промпт не зашивается в код: это прямое требование ТЗ. У каждого промпта есть версия, изменения фиксируются.
- **Изменение архитектуры — только через ADR** в `docs/04-architecture/adr/`. Обнаружил, что архитектура не работает — останавливайся и пиши ADR, а не обходи её в коде.
- **Детерминированные слои остаются детерминированными.** Парсинг, верстка и экспорт не вызывают модели. Соблазн «спросить LLM, куда поставить блок» ломает воспроизводимость и вместе с ней весь детерминированный аудит.
- **Ни один слайд не выгружается растром.** Требование ТЗ; проверяется тестом, а не на глаз.
- **Не подстраивайся под калибровочные шаблоны.** Условие вида «если шаблон VK Tech, то…» — прямое нарушение требования ТЗ о работе с произвольным шаблоном. Шаблон из `assets/templates/acceptance/` не используется для отладки.
