# Цифровой дизайнер презентаций

Сервис создания презентаций на основе текстового описания и предзагруженных шаблонов.

## Краткое описание

Сервис закрывает разрыв между способностью LLM писать содержание и её неспособностью воспроизводить дизайн-систему компании. Система читает чужой шаблон как набор правил и собирает по нему новые слайды, соответствующие корпоративному уровню.

## Ключевые возможности

- Импорт и декомпозиция шаблонов презентаций
- Генерация структуры и содержания по брифу
- Генерация слайдов в контексте шаблона
- Генерация графиков, таблиц, диаграмм, SmartArt
- Аудит сгенерированных слайдов (детерминированный + контекстуальный)
- Три варианта верстки для одного шаблона и контента
- Экспорт в .html, .pptx (нативные объекты), .pdf

## Статус

Проект в фазе реализации. Проектирование завершено, архитектура утверждена.

**Работает сквозной путь:** шаблон `.pptx` разбирается в схему правил, колода верстается детерминированно по макетам шаблона, выгружается в редактируемый `.pptx` нативными объектами и рендерится в изображения — в трёх визуально различимых вариантах, с нативными таблицами и диаграммами. Проверено на трёх шаблонах, 591 тест.

Разбор шаблона реализован полностью: цепочка наследования свойств, дизайн-токены частотным анализом разметки, слоты из плейсхолдеров, фигур и свободных областей, классификация макетов по структуре, метрика качества разметки, вид фона, цветовые вариации макетов.

**Аудит работает целиком в детерминированной части:** 26 проверок из 37 — вёрстка, соответствие шаблону, плотность, целостность и гибридный контраст, — автоматическое исправление механических находок с откатом и защитой от ухудшения, исправление находок с потерями по выбору пользователя с повторной проверкой, подсветка находок на изображении слайда. Оставшиеся одиннадцать относятся к валидации контента и требуют модели.

**Все три обязательных формата выгрузки работают:** `.pptx` нативными объектами, `.pdf` через LibreOffice с проверкой числа страниц, `.html` — самодостаточная страница, где текст остаётся текстом, таблицы таблицами, а диаграммы рисуются вектором.

**Интерфейс работает:** `streamlit run ui/app.py` открывает страницу, где путь проходится целиком — загрузка шаблона, диагностика разбора, план колоды, прогресс по этапам, три варианта рядом, выбор варианта, замечания проверки с выбором исправления и скачивание готовых файлов. Страница говорит словами пользователя, а не вёрстки: подробности для дизайнера свёрнуты, жаргон на виду ловит тест.

Слой генерации по брифу ещё не написан: план колоды пока вводится руками, строка без знака — заголовок слайда, строка с «-» — его пункт. Пакетная генерация девяти колод (T-42) тоже впереди. Текущее состояние — в `docs/00-status.md`.

## Требования

- Десктопная платформа: Windows или macOS
- Браузер: актуальная и предыдущая версии Chrome, Firefox, Safari, Яндекс Браузер
- Python 3.12+
- **LibreOffice** — обязателен: конвертация в PDF и рендер слайдов в изображения
- Доступ к внешнему API-провайдеру открытых моделей либо GPU для локального инференса. Для модели на 32B нужно около 20 ГБ VRAM в 4-битном квантовании; на машине разработки такого GPU нет, поэтому используется внешний провайдер

### Размещение

Тяжёлые компоненты выносятся на диск с запасом места: виртуальное окружение занимает около 420 МБ, LibreOffice — около 350 МБ, а каждый прогон порождает рендеры слайдов и три варианта колоды в трёх форматах. Каталог результатов задаётся переменной `DPD_OUTPUT_DIR`.

Поддержка мобильных устройств и планшетов не требуется и не планируется.

## Быстрый старт

Стек: Python 3.12 и Streamlit (решение ADR-0005). Работают установка окружения и тесты; команды запуска интерфейса и пакетной генерации описывают целевой сценарий — соответствующие слои ещё не реализованы.

**Пути в примерах — не требование.** `D:\venvs\dpd` и `D:\LibreOffice` взяты с машины разработки, где на системном диске мало места. Подставляйте свои: код этих путей не знает, всё внешнее задаётся переменными окружения `SOFFICE_PATH` и `DPD_OUTPUT_DIR`.

```bash
# Окружение (на диске с достаточным местом — см. «Размещение»)
python -m venv D:\venvs\dpd
D:\venvs\dpd\Scripts\python -m pip install -r scripts/requirements.txt

# Сам проект — обязательный шаг, не опциональный
D:\venvs\dpd\Scripts\python -m pip install -e .

# Переменные окружения
cp .env.example .env
# заполнить .env — см. раздел ниже

# Веб-интерфейс
D:\venvs\dpd\Scripts\streamlit run ui/app.py

# Пакетная генерация девяти демонстрационных колод
D:\venvs\dpd\Scripts\python scripts/generate_all.py \
    --templates ./assets/templates/calibration \
    --content ./assets/content-pack

# Тесты
D:\venvs\dpd\Scripts\pytest
```

Пропустить `pip install -e .` нельзя: пакет живёт в `src/`, и путь к нему прописывается в окружение при установке. Без этой команды `import dpd` не сработает, а тесты упадут с `ModuleNotFoundError: dpd` — выглядеть это будет как сломанный код, хотя сломан будет только сетап.

Состав окружения закреплён точными версиями в `scripts/requirements.txt`, включая транзитивные зависимости. Файл — источник истины: если тесты сообщают о расхождении версий, приводите окружение к файлу, а не наоборот.

## Переменные окружения

Обязательные требования ТЗ к разделу. Значения задаются в `.env` (файл не коммитится), шаблон — в `.env.example`.

| Переменная | Назначение | Пример / по умолчанию |
|---|---|---|

| `LLM_BASE_URL` | Адрес API-эндпоинта основной LLM | `http://localhost:8000/v1` |
| `LLM_API_KEY` | Ключ доступа к API-провайдеру | — |
| `LLM_MODEL` | Идентификатор основной модели | `Qwen/Qwen2.5-32B-Instruct` |
| `VLM_BASE_URL` | Эндпоинт VLM для недетерминированного аудита | `http://localhost:8001/v1` |
| `VLM_MODEL` | Идентификатор VLM | `Qwen/Qwen2.5-VL-7B-Instruct` |
| `T2I_ENABLED` | Включить генерацию изображений (задача со звёздочкой) | `false` |
| `T2I_MODEL` | Модель text-to-image | `black-forest-labs/FLUX.1-schnell` |
| `SOFFICE_PATH` | Путь к LibreOffice для рендера и PDF | `D:\LibreOffice\program\soffice.com` |
| `DPD_OUTPUT_DIR` | Каталог результатов генерации и промежуточных артефактов | `D:\dpd-out` |

| `LOG_LEVEL` | Уровень логирования | `INFO` |

## Ограничения

Обязательный раздел по ТЗ. Ограничения делятся на заданные заданием и вытекающие из выбранной архитектуры.

### Заданные ТЗ

- Целевой объём колоды — 10–15 слайдов либо число, указанное пользователем.
- Время генерации одной колоды — не более 5 минут.
- Только модели с открытыми весами, лицензии Apache 2.0 / MIT, до 35B (text-to-image до 20B).
- Экспорт в PPTX — только нативными объектами; слайд, выгруженный единым растровым изображением, не засчитывается.
- Решение не должно быть заточено под три калибровочных шаблона: на защите используется ранее не виденный шаблон.

### Вытекающие из архитектуры

- Поддерживаются шаблоны в формате `.pptx` и `.potx`. Формат `.ppt` требует предварительной конвертации.
- Шаблон должен содержать хотя бы один мастер и один макет; шаблоны без макетов не поддерживаются.
- Дизайн-токены извлекаются из фактической разметки, а не из темы: тема в реальных корпоративных шаблонах систематически расходится с тем, что используется на слайдах (см. `docs/01-research/template-analysis.md`).
- Шрифты шаблона должны быть установлены в системе для корректного рендера превью и PDF; иначе LibreOffice подставит замену и результат превью будет приблизительным.
- Недетерминированные проверки аудита выполняются моделью и на повторных запусках могут дать разный ответ. Воспроизводимость гарантируется только для детерминированной части.
- Для находок с потерями пока реализован один способ исправления — перенос части пунктов на новый слайд. Для остальных таких находок интерфейс сообщает, что готового способа нет. Откат автоматических исправлений есть в коде, но не выведен в интерфейс.

## Структура репозитория

```text
src/dpd/                       исходный код, подкаталоги повторяют слои пайплайна
tests/                         модульные и интеграционные тесты
assets/templates/calibration/  калибровочные шаблоны VK — в репозиторий не включены
assets/templates/acceptance/   приёмочный шаблон для end-to-end демонстрации
assets/templates/edge-cases/   входы, которые формально .pptx, но шаблонами не являются
assets/content-pack/           контент-пакет (наш артефакт, один на все прогоны)
prompts/skills/                промпты скиллов, версионируются отдельно от кода
prompts/agents/                промпты агентов
docs/                          проектная документация по фазам
scripts/                       служебные скрипты и requirements.txt
```

### Исходные материалы и что из них опубликовано

Калибровочные шаблоны VK Tech, VK WorkSpace и VK Education получены от организаторов хакатона как рабочий материал. **Сами файлы в репозиторий не включены** — каталог `assets/templates/calibration/` пуст, шаблоны исключены через `.gitignore`. Разрешения на их публикацию у нас нет, и мы его не предполагаем.

Опубликованы только производные выводы: результаты инструментального разбора OOXML — распределения кеглей, доли наследуемых свойств, число макетов и слотов, метрики качества разметки. Они собраны в `docs/01-research/` и нужны потому, что на них опираются все архитектурные решения проекта: без оснований эти решения выглядели бы произвольными. Чтобы воспроизвести разбор, положите свои файлы в `assets/templates/calibration/` — инструкция в README этого каталога.

Приёмочный шаблон `Jessica · SlidesCarnival.pptx` в репозитории **присутствует**: он распространяется под Creative Commons Attribution 4.0 International, что публикацию разрешает. Атрибуция — в `assets/templates/acceptance/README.md`, как того требует лицензия.
