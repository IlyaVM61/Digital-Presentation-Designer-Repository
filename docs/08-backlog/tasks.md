# Бэклог задач

Задачи реализации в порядке выполнения. Артефакты сдачи и их критерии приёмки — `deliverables.md`.

Дата: 2026-09-29. Фаза 10.

**Приоритеты:** `P0` — без этого нет решения; `P1` — требуется для промежуточной сдачи; `P2` — улучшает результат.

Каждая задача несёт критерий приёмки: формулировка, к которой нельзя придумать проверку, задачей не является.

## Принцип порядка: начинаем с самого рискованного

Обычный порядок — парсинг, генерация, вёрстка, аудит, экспорт — здесь неверен. Он откладывает проверку главного технического риска на последний момент.

**Главный риск — нативный экспорт PPTX.** ТЗ прямо не засчитывает слайд, выгруженный растром. Если собрать нативные объекты не удастся, обесценится вся остальная работа, и узнать об этом нужно в первый день, а не в последний.

Второй по величине риск — **рендер слайдов**: от него зависят три из четырёх мест архитектуры, а LibreOffice ещё не проверен на наших шаблонах.

Поэтому первый этап — сквозной вертикальный срез: минимальный путь от шаблона до редактируемого `.pptx`, без генерации, без аудита, без интерфейса. Он проверяет оба риска за несколько задач.

**Второй принцип: детерминированный контур раньше моделей.** Доступа к API-провайдеру нет (T10), и это не должно останавливать работу. Парсинг, вёрстка, экспорт и проверки класса `file` — три четверти аудита — делаются без моделей.

| T-48 | Загрузка и версионирование промптов из `prompts/` | P0 | В коде нет ни одного промпта; версия набора попадает в `AuditReport` |
| T-49 | Генерация структуры колоды по брифу | P0 | 10–15 слайдов, каждый с ролью и ключевым сообщением |
| T-50 | Генерация содержания слайдов с `sourceRefs` | P0 | Каждое число на слайде прослеживается до контент-пакета |
| T-51 | Аудит текста: 9 проверок класса `model` | P1 | Выполняется один раз на колоду до вёрстки |
| T-52 | Аудит визуала через VLM | P1 | Один запрос на слайд, все вопросы разом |
| T-53 | Верификация токенов через VLM | P2 | Расхождение понижает `confidence`, не переписывая схему |

## Что не делается

- Генерация изображений внутри слайда (FR-27) — исключена решением D7.
- Документы алгоритмов — фаза 8 исключена.
- Питч, фиксация версии тегом, воспроизводимый сетап конфиг-файлом — требования финальной сдачи, сняты с текущего плана.

## Порядок работы

Одна задача за раз. Тест пишется до реализации и падает до неё. Задача считается выполненной, когда тесты прогнаны и их вывод показан — не тогда, когда код написан.

Изменение архитектуры по ходу реализации оформляется через ADR, а не обходится в коде.
