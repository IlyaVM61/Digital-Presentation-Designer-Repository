# Матрица покрытия типов слайдов

Документ показывает, какие типы слайдов поддерживает каждый калибровочный шаблон. Цель — понять, какие типы пайплайн может сгенерировать на любом шаблоне, а какие есть лишь в некоторых, то есть где обязателен фолбэк.

Дата: 2026-09-29. Источник данных — разбор макетов, плейсхолдеров и слайдов-примеров, см. `template-analysis.md`.

## Как читать матрицу

- **да** — есть макет с явной семантической разметкой под этот тип: подходящие плейсхолдеры либо однозначно узнаваемая структура слотов.
- **структурно** — геометрия макета позволяет собрать такой слайд, но семантической разметки нет: слоты не размечены плейсхолдерами, а имя макета не отражает назначение. Требует распознавания слотов из обычных фигур.
- **нет** — макета под этот тип не найдено.

## Выводы

### Ни один тип слайда не покрыт явной разметкой во всех трёх шаблонах

Пересечение столбца «да» по трём шаблонам пусто: VK WorkSpace не имеет ни одного макета с семантической разметкой, поскольку у всех его 15 макетов есть только плейсхолдер заголовка.

Прямое следствие: **пайплайн не может опираться на наличие семантически размеченных макетов ни для одного типа слайда.** Распознавание слотов из обычных фигур — не фолбэк для крайнего случая, а основной режим работы. На неизвестном шаблоне комиссии ситуация с высокой вероятностью будет такой же.

### Три шаблона задают три разных уровня сложности

- **VK Education** — эталон для отладки: 8 типов из 10 размечены явно, есть PICTURE-плейсхолдеры, осмысленные имена макетов. На нём базовый сценарий должен работать сразу.
- **VK Tech** — средний случай: разметка бедная (в большинстве макетов только заголовок), но семейства макетов выражены в именах и различимы по структуре.
- **VK WorkSpace** — тяжёлый случай: семантики нет вовсе, имена макетов бесполезны (11 из 15 называются «Титульный слайд»), тип слайда выводится только из геометрии слотов.

Порядок отладки должен идти от Education к WorkSpace, а не наоборот. Решение, работающее только на Education, провалится на защите.

### Два типа слайдов не покрыты нигде, кроме Education

**Цитата** и **данные/KPI** есть только в VK Education. При этом контент-пакет содержит и цитаты, и числовые ряды — то есть на двух других шаблонах эти блоки придётся размещать на общих контентных макетах. Это нормальная ситуация, но она должна быть осознанным решением слоя верстки, а не случайностью: пайплайн обязан уметь деградировать тип слайда до ближайшего доступного.

### Отсутствие PICTURE-плейсхолдеров в двух шаблонах из трёх

Ни VK Tech, ни VK WorkSpace не имеют ни одного плейсхолдера типа PICTURE. При этом изображения в них используются активно — но как элементы оформления макета, включая фон-изображение на весь слайд (24 макета из 39 в VK Tech).

Следствие для задачи со звёздочкой (генерация изображений внутри слайда): место под изображение в большинстве шаблонов не размечено, и его придётся определять из свободной геометрии слота. Требование «встроить визуализацию с учётом правил композиции и ограничений макета» на таких шаблонах существенно сложнее, чем на шаблоне с PICTURE-плейсхолдерами.

### Диаграмм нет ни в одном шаблоне

Отдельный и самый неприятный факт: в 138 слайдах-примерах трёх шаблонов **ни одной диаграммы**. Таблиц всего четыре, SmartArt — ноль. Ни один шаблон не содержит ни макета под данные (кроме «2 фактоида» в Education), ни примера оформления диаграммы.

Это означает, что правила оформления диаграмм из шаблонов **извлечь невозможно** — их там нет. Оформление придётся выводить из дизайн-токенов: палитры, типографической шкалы, отступов. Подробнее — в `template-analysis.md`, вывод 5.

## Что матрица означает для пайплайна

1. **Тип слайда выводится из геометрии слотов, а не из разметки.** Явная разметка — приятный бонус, встречающийся в одном шаблоне из трёх.
2. **Нужна деградация типов.** Если запрошенного типа в шаблоне нет, слой верстки выбирает ближайший доступный и сообщает об этом, а не отказывается работать.
3. **Нужна метрика качества разметки шаблона.** По ней парсер решает, доверять ли плейсхолдерам и именам макетов или полагаться на геометрию. Кандидаты в метрику: доля макетов с более чем одним плейсхолдером, доля уникальных имён макетов, наличие PICTURE-плейсхолдеров.
4. **Оформление диаграмм и таблиц синтезируется из токенов,** а не копируется из шаблона.
