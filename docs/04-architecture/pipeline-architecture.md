# Архитектура пайплайна

Пять слоёв с явными контрактами. Документ детализирует корневой `ARCHITECTURE.md` и опирается на решения из `solution-architecture.md`.

Дата: 2026-09-29.

## Принцип контракта

Контракт слоя описывает три вещи: что на входе, что на выходе и **чего слой принципиально не делает**. Третье не менее важно: именно запреты держат границу между смыслом и формой, а на ней стоит воспроизводимость.

Все контракты — сериализуемые структуры. Любой слой можно запустить изолированно, подав ему файл с входом: это нужно для тестов и для демонстрации устройства пайплайна на защите.

## Слой 1: Парсинг

**Вход:** бинарный файл `.pptx` или `.potx`.
**Выход:** `TemplateSchema` — см. `template-schema.md`.

**Компоненты**

| Компонент | Ответственность |
|---|---|
| Распаковщик пакета | Чтение OOXML-частей, разрешение связей между ними |
| Разрешатель наследования | Восстановление свойств по цепочке прогон → абзац → макет → мастер → тема |
| Извлекатель токенов | Частотный анализ фактической разметки: палитра, гарнитуры, шкала кеглей, отступы |
| Распознаватель слотов | Плейсхолдеры и обычные фигуры макета → слоты с типом, выведенным из геометрии |
| Классификатор макетов | Функциональный тип макета из структуры слотов; группировка в варианты по оформлению |
| Оценщик разметки | Метрика `markupQuality` и выбор стратегии разбора |
| Верификатор токенов | Опционально: подтверждение токенов по рендеру слайда-примера через VLM |

**Чего слой не делает**

- Не знает о контенте, брифе и назначении колоды.
- Не принимает решений о том, какой слайд на каком макете будет собран.
- Не переписывает шаблон: файл открывается только для чтения.
- Не считает абсолютные координаты в выходной схеме — только доли холста.

**Требования, которые реализует:** FR-1 – FR-9.

## Слой 2: Генерация

**Вход:** бриф, контент-пакет, `TemplateSchema`.
**Выход:** `PresentationStructure`.

```json
{
  "meta": {
    "purpose": "initiative",
    "audience": "руководители подразделений",
    "language": "ru",
    "slideCount": 12
  },
  "slides": [
    {
      "id": "s4",
      "role": "data",
      "headline": "Пилот окупился за четыре квартала",
      "keyMessage": "Экономия 9,4 млн ₽ против затрат 2,8 млн ₽",
      "body": { "kind": "bullets", "items": ["…", "…"] },
      "visualization": {
        "kind": "chart",
        "chartType": "column",
        "series": [{ "name": "Активных пар", "points": [18, 34, 61, 96] }],
        "categories": ["IV кв. 2025", "I кв. 2026", "II кв. 2026", "III кв. 2026"],
        "axisTitles": { "value": "пар", "category": "квартал" }
      },
      "sourceRefs": ["content.md#масштаб-пилота"]
    }
  ]
}
```

**Ключевое свойство контракта:** здесь нет ни одной координаты, ни одного кода цвета, ни одного названия шрифта и ни одного идентификатора макета. Структура описывает, **что** сказать и **чем** это показать, но не **как** это выглядит.

Поле `sourceRefs` обязательно: на нём держится проверка «все цифры и факты со слайда есть в исходных материалах» (Приложение 1 ТЗ, п. 4 валидации контента). Без ссылки на источник эту проверку пришлось бы выполнять поиском по тексту, что ненадёжно.

**Компоненты**

| Компонент | Ответственность | Модель |
|---|---|---|
| Анализатор брифа | Назначение, аудитория, объём, язык | LLM |
| Генератор структуры | Состав и последовательность слайдов, роли | LLM |
| Генератор содержания | Заголовки-выводы, тексты, ключевые сообщения | LLM |
| Планировщик визуализаций | Тип визуализации и данные для неё из контент-пакета | LLM |

**Чего слой не делает**

- Не выбирает макет и не знает о геометрии шаблона.
- Не задаёт цвета, шрифты, кегли и координаты.
- Не выдумывает числа: любое число в `visualization` и в тексте должно иметь `sourceRefs`.
- Не решает, поместится ли содержимое: это ответственность вёрстки.

**Валидация:** каждый ответ модели проверяется по JSON Schema. При невалидном ответе — повторный запрос с указанием ошибки, ограниченное число попыток. Невалидный ответ никогда не передаётся дальше по пайплайну.

**Требования:** FR-10 – FR-14, FR-26 (в части плана визуализации).

## Слой 3: Вёрстка

**Вход:** `PresentationStructure`, `TemplateSchema`, параметры варианта.
**Выход:** три `RenderedPresentation`.

```json
{
  "variant": "A",
  "templateHash": "…",
  "canvas": { "widthEmu": 9144000, "heightEmu": 5143500 },
  "slides": [
    {
      "id": "s4",
      "layoutId": "master1/layout8",
      "layoutFamily": "content",
      "elements": [
        {
          "slotId": "title",
          "kind": "text",
          "bounds": { "x": 0.02, "y": 0.05, "w": 0.44, "h": 0.14 },
          "runs": [{ "text": "Пилот окупился…", "font": "Play", "sizePt": 18, "color": "#000000", "bold": true }]
        },
        { "slotId": "body-1", "kind": "chart", "bounds": { … }, "spec": { … } }
      ],
      "appliedCompensations": [
        { "kind": "fontScale", "slotId": "title", "from": 18, "to": 16, "reason": "текст не помещался в две строки" }
      ]
    }
  ]
}
```

Координаты нормализованы; абсолютные EMU появляются только на экспорте. Поле `appliedCompensations` обязательно — на нём держится требование FR-18 сообщать пользователю о применённых компенсациях и проверка QR-5 о выходе за типографическую шкалу.

**Компоненты**

| Компонент | Ответственность |
|---|---|
| Селектор макета | Подбор макета по типу слайда, числу и характеру слотов; деградация типа при отсутствии подходящего |
| Укладчик содержимого | Размещение текста и визуализаций в слотах, применение токенов |
| Обработчик переполнения | Компенсации в границах правил шаблона, с фиксацией каждой |
| Генератор визуализаций | Диаграммы, таблицы, схемы и пиктограммы, оформленные по токенам шаблона |
| Генератор вариантов | Три варианта по выбранной оси различий |

**Чего слой не делает**

- Не вызывает LLM и VLM. Ни для выбора макета, ни для сокращения текста.
- Не меняет содержание: текст приходит готовым из слоя 2.
- Не пишет файлы презентаций: это ответственность экспорта.
- Не скрывает компенсации: любое отклонение от исходного замысла попадает в `appliedCompensations`.

Запрет на вызов моделей — не догма, а следствие: если выбор макета станет вероятностным, детерминированные проверки «слайд собран не на макете из шаблона» и «блоки не выровнены» перестанут быть воспроизводимыми.

**Требования:** FR-15 – FR-26.

## Слой 4: Аудит

Разделён на три подслоя, выполняющихся в разные моменты и на разных представлениях. Обоснование — решение 1 в `solution-architecture.md`. Полный перечень проверок — фаза 6.

### 4a. Аудит текста

**Вход:** `PresentationStructure` и контент-пакет. **Выход:** находки класса `text`.
**Когда:** после слоя 2, **до вёрстки**. **Сколько раз:** один раз на колоду.
**Чем:** LLM.

Проверяет смысл: заголовок содержит вывод, а не называет тему; содержимое соответствует заголовку; цифры прослеживаются до `sourceRefs`; язык единый; соседние слайды связаны логически; нет служебного мусора.

Выполняется до вёрстки потому, что находки этого класса правятся перегенерацией текста — обнаруживать их после того, как свёрстаны три варианта, поздно и дорого.

### 4b. Аудит формы

**Вход:** `RenderedPresentation`, `TemplateSchema`. **Выход:** находки класса `deterministic`.
**Когда:** после вёрстки. **Сколько раз:** для каждого из трёх вариантов.
**Чем:** ничего, чистая логика.

Проверяет вёрстку, соответствие шаблону, плотность и целостность: выход за границы, наложения, непоместившийся текст, шрифт и кегль вне допустимого состава шаблона, цвет вне палитры, число буллетов, размер таблиц, растровый слайд, текст-заглушка, дубликаты слайдов.

Дешёвый подслой: выполняется целиком по данным, без рендера и без моделей, поэтому применяется ко всем вариантам всегда.

### 4c. Аудит визуала

**Вход:** рендеры слайдов. **Выход:** находки класса `visual`.
**Когда:** после вёрстки. **Сколько раз:** для выбранного варианта; полный прогон по всем трём — по явному требованию пользователя.
**Чем:** VLM.

Проверяет то, что видно только на изображении: уместность изображений и пиктограмм теме слайда, читаемость, контраст текста к фону там, где фон является изображением и код цвета не существует.

**Выход слоя:** `AuditReport`.

```json
{
  "runId": "…", "variant": "A",
  "findings": [
    {
      "id": "f7",
      "check": "template.font_not_in_scale",
      "category": "template",
      "kind": "deterministic",
      "severity": "warning",
      "fixability": "mechanical",
      "slideId": "s4", "slotId": "title",
      "message": "Кегль 16,2 pt отсутствует в типографической шкале шаблона",
      "confidence": 0.9,
      "status": "autofixed",
      "evidence": { "expected": [14, 16, 18], "actual": 16.2 }
    }
  ],
  "timings": { "parse": 12.4, "generate": 71.0, "layout": 6.2, "audit": 48.1, "export": 9.3 }
}
```

Поля `fixability` и `status` реализуют политику D5; `confidence` наследуется от уверенности использованных токенов и позволяет показывать слабо обоснованную находку как рекомендацию, а не как ошибку. Поле `timings` реализует NFR-1а.

**Чего слой не делает**

- Не правит слайды сам: применением исправлений занимается фиксер по политике D5.
- Не блокирует экспорт: решение принимает пользователь.
- Не выдаёт находку, полученную по рендеру, за детерминированную — класс проверки указан явно.

**Требования:** FR-28 – FR-34, FR-42 – FR-46, QR-1 – QR-6.

## Слой 5: Экспорт

**Вход:** `RenderedPresentation`, прошедшая аудит. **Выход:** файлы.

| Экспортёр | Особенность |
|---|---|
| `.pptx` | Только нативные объекты: текстовые рамки, таблицы, диаграммы, группы. Здесь нормализованные доли пересчитываются в EMU под холст шаблона |
| `.html` | Статическое представление колоды |
| `.pdf` | Через рендер |

**Чего слой не делает**

- Не меняет содержание и композицию.
- Не растеризует слайды: слайд, ставший изображением, — дефект по ТЗ, и это проверяется (FR-38).
- Не досчитывает то, чего нет в `RenderedPresentation`: все решения приняты раньше.

**Требования:** FR-35 – FR-38.

## Оркестрация

Линейный проход: парсинг → генерация → аудит текста → вёрстка × 3 → аудит формы × 3 → аудит визуала → исправления → экспорт. Каждый этап порождает событие прогресса и запись в `timings`.

**Обратная связь ограничена одной операцией:** «перегенерировать слайд N». Она проходит подпайплайн только для этого слайда — генерация содержания, вёрстка, аудит, — не затрагивая остальные и не меняя структуру колоды. Ограничения цикла заданы решением D5.

## Версионирование

Промпты и конфиги скиллов лежат отдельными файлами в `prompts/` и версионируются независимо от кода. Каждому прогону соответствует зафиксированный набор версий, который попадает в `AuditReport`: без этого воспроизводимость недетерминированной части непроверяема.
