# Стратегия 3 вариантов верстки

## Требование ТЗ

«Представление результата генерации в трех вариантах верстки для одного и того же шаблона и контента. Ось различий команда определяет сама (например: выбор макетов, плотность контента, порядок и группировка слайдов, способ визуализации данных) и обосновывает свой выбор в документации. Варианты должны быть визуально различимы и при этом одинаково соответствовать правилам шаблона.»

## Предлагаемая ось различий

### Ось 1: Плотность контента

- **Вариант A — Sparse (разреженный):** минимум текста, больше пустого пространства, крупные изображения, 1–2 буллета на слайд.
- **Вариант B — Balanced (сбалансированный):** стандартная плотность, 3–4 буллета, смешанное использование текста и визуалов.
- **Вариант C — Dense (плотный):** максимум информации, 5–6 буллетов, таблицы и графики там, где возможно.

**Обоснование:** плотность — ключевой параметр восприятия презентации. Разные аудитории (топ-менеджмент, инженеры, клиенты) требуют разной плотности. Все три варианта остаются в рамках правил шаблона.

### Ось 2: Способ визуализации данных (альтернатива)

- **Вариант A — Textual:** данные в виде маркированных списков и выделенных чисел.
- **Вариант B — Graphical:** данные в виде диаграмм и графиков.
- **Вариант C — Hybrid:** комбинация таблиц, графиков и текстовых выводов.

### Ось 3: Порядок и группировка слайдов

- **Вариант A — Linear:** последовательное повествование.
- **Вариант B — Problem-Solution:** сгруппировано по проблемам и решениям.
- **Вариант C — Modular:** слайды-модули, которые можно переставлять.

## Выбор

Рекомендуется **Ось 1 (плотность)** как основная, потому что:
- Она максимально наглядна.
- Она не меняет смысл презентации, только подачу.
- Она демонстрирует гибкость движка верстки.
- Она хорошо видна на статичных скриншотах для комиссии.

## Техническая реализация

В движке верстки добавляется параметр варианта:

```typescript
type DensityLevel = 'sparse' | 'balanced' | 'dense';

interface VariantParams {
  densityLevel: DensityLevel;
}
```

## Статус решения

`ОТЛОЖЕНО ДО ФАЗЫ 7` Окончательный выбор оси различий не принят. Решение принимается после фазы 2 (анализ шаблонов), когда будет видно, насколько жёстко шаблоны ограничивают композицию.

Причина отсрочки: ТЗ требует, чтобы варианты были **визуально различимы**. Разбор калибровочных шаблонов показал, что в двух из трёх шаблонов у большинства макетов есть только плейсхолдер заголовка, а контент размечен обычными фигурами (см. `docs/01-research/template-analysis.md`). На таких шаблонах свобода перекомпоновки ограничена, и одна лишь плотность контента может дать три слабо различимых колоды.

Кандидат на замену, если риск подтвердится: связка «плотность + способ подачи данных» (текст / диаграмма / гибрид), дающая гарантированно заметную разницу при одинаковом соответствии правилам шаблона.
