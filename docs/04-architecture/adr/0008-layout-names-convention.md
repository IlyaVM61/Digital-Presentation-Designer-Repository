# ADR-0008. Имя макета сильнее геометрии, когда договорённости об именах следуют все макеты

Дата: 2026-10-02. Статус: принято.

Закрывает открытый вопрос T28 (решение владельца 2026-10-02: задача T-62, вариант (а)). Уточняет установленный факт «имена макетов ненадёжны» (`docs/01-research/template-analysis.md`, вывод 4) и раздел «Отвергнутые варианты» в `template-schema.md`: определять тип макета по имени по-прежнему нельзя, если шаблон не объявил договорённость сам.

## Контекст

Тип макета выводится из геометрии слотов (T-14): в калибровочном шаблоне 11 макетов из 15 называются «Титульный слайд», и имя назначения не отражает.

Есть шаблоны, где имя — заявление автора: макеты названы по договорённости префиксом назначения — `title*` (обложка), `section*` (раздел), `slide*` (обычный слайд), `table*` (слайд с таблицей), `last*` (финал), — а поля размечены типизированными плейсхолдерами: заголовок, тело, таблица, картинка.

Проверка разбором на примере такого шаблона (2026-10-02, подробности вне публичного репозитория) показала: заголовок и тело разбор находит по типу плейсхолдера, но

- обложка, раздел и финал одной геометрии попадают в одно семейство `title`, и варианты B и C ставят обложку колоды на макет раздела и на финальный;
- плейсхолдер таблицы считается прочим: таблица ложится в текстовое поле, а поле таблицы остаётся пустым;
- макет из полей таблицы и картинки без тела получает место под текст, построенное поверх обоих полей, и вариант A кладёт на него все текстовые слайды;
- макет с полем картинки берётся под текстовые слайды, и половина слайда пустует.

## Решение

**Имя — сигнал, только когда договорённости следуют все макеты шаблона.** Имя каждого макета начинается с одного из пяти префиксов, с учётом регистра. Тогда у макета есть назначение (`Layout.purpose`), тип выводится из назначения (`familySource: name`): обложка и финал — `title`, раздел — `section`, обычному слайду и слайду с таблицей тип по-прежнему даёт геометрия — одно место или несколько. Если вне договорённости хоть один макет — назначения нет ни у одного, и всё как прежде.

**Выбор макета сначала по назначению.** Роль слайда даёт назначение: титул — обложка, раздел — раздел, финал — финал, слайд с таблицей — слайд с таблицей, остальное — обычный. Содержимое важнее роли, как и без имён: раздел или финал со списком идёт на обычный слайд. Внутри назначения выбор идёт по типу, как прежде, со смещением вариантов. Если нужного назначения в шаблоне нет — ближайшее (раздел → обычный; обложка и финал друг друга не подменяют), и отступление записывается в решение о макете.

**Пока картинок нет, макет с полем картинки уступает макету того же назначения без него** (решение владельца 2026-10-01). Если другого нет — берётся он.

**Общее, без имён:**

- плейсхолдер таблицы — слот `table`, плейсхолдер картинки — слот `picture`, а не прочее;
- таблица ложится в поле таблицы; у таблицы со своим полем тело слайда ложится в текстовое поле рядом; экспорт вставляет таблицу в сам плейсхолдер, и она остаётся полем шаблона;
- таблице макет с полем таблицы идёт раньше макета с бо́льшим местом: поле под таблицу автор отвёл сам;
- поля таблицы и картинки — препятствия для места, которое разбор строит в свободной области; элементы, стоящие вплотную друг к другу, сдвигают его границу цепочкой.

## Почему так

**Почему все макеты, а не большинство.** Одно случайное совпадение префикса ничего не говорит: среди имён редакторов есть «Title Slide», «Title and Content», и порог «большинство» пришлось бы подбирать. Требование «все» не нуждается в пороге и не срабатывает на шаблоне, где имена — след дублирования. Регистр — по той же причине: имена редакторов пишутся с заглавной («Title Slide», «TITLE_AND_BODY»).

**Почему префиксы в коде, а не в конфиге.** Разбор кешируется по хешу файла и версии разбора; префиксы из конфига в ключ кеша не входят, и правка конфига молча не действовала бы на уже разобранные шаблоны. Договорённость — правило разбора, как порог «шапки» заголовка, и меняется вместе с версией разбора.

**Почему поле картинки уступает, а не заполняется.** Изображений в полуфинале нет (решение владельца 2026-10-01); пустое поле картинки на слайде — пустая половина.

## Отвергнутые варианты

- **(б) То же плюс оформление таблиц по образцу из шаблона.** Смысл образца договорённость не описывает — сначала ответ организаторов.
- **(в) Только общее, без имён.** Меньше работы, но обложка на финальном макете остаётся.
- **Доверять имени каждого макета по отдельности.** Ломает калибровочные шаблоны: «Титульный слайд» на 11 макетах из 15.

## Последствия

- В схеме шаблона новые виды слотов `table`, `picture` и поле `Layout.purpose`; версия разбора — 0.4.0, разобранные прежде шаблоны разбираются заново.
- На шаблонах без договорённости меняется только то, что касается полей таблицы и картинки; калибровочные проверены сборкой «до и после» (handoff, раздел о T-62).
- Шаблон с договорённостью, где обычный макет один, даёт вариантам один и тот же макет обычного слайда: варианты различаются кеглем и цветовой схемой, а не макетом. Это свойство шаблона, а не дефект выбора.
- Поля, размеченные обычными фигурами с именами по договорённости, а не плейсхолдерами, не поддерживаются: это отдельная задача, если шаблон с такой разметкой понадобится.
